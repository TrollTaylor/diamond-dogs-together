# Two-player death and respawn

Version **0.10.11** connects the scoped death policy and local respawn controller to the companion native respawn-health rule. Version 0.10.10 contained the script path without this native adaptation. It compiles but has not been installed, tested or executed in MGSV. This is implementation progress, not evidence of successful death recovery or playable co-op.

Dynamite disables `TppMission.OnPlayerDead` and handles `Player.DeadInFOB` by starting a ten-second timer, resetting four HUD statuses and calling `Player.RequestToRespawn`. This adaptation preserves the original death handler and delegates it unless an owned, established two-player co-op context authorizes the replacement. Unrelated mission failures are unchanged.

The native context reader accepts this adapter's tracked host in state 3 or established client in state 7, on the creation thread, with matching main-session/network-owner pointers and exact session/member types. It requires both present player indices 0 and 1 and checks the local member identity. Lua compares that identity with `PlayerInfo.GetLocalPlayerIndex`. It uses the same mapped roster and published-life-state layout as targeting; respawn reads do not require a valid position, which could be unavailable during a fall death. No local identity or native death flag is written.

For a local death, a game timer waits ten seconds. Duplicate death events do not restart it. Remote deaths can suppress the host's ordinary player-death failure, but never request a respawn of the host's local actor. Requests run after normal mission update, outside death/timer message dispatch. Each death receives distinct timer names so a delayed timer event from an earlier death cannot trigger the next respawn early.

After a request returns, the controller watches the published DEAD bit and starts a fifteen-second confirmation timer. A cleared bit is recorded as `alive_observed`, not proof of recovered control or synchronized gameplay. Eight consecutive unavailable context samples, changed local identity, a thrown request or an elapsed confirmation timer can invoke the saved original death behavior. A single changing publication sample does not immediately end the recovery. If the confirmation timer itself throws after the request has already returned, the error is recorded and life-state observation continues without issuing a duplicate request. Original mission update/termination return values, errors and yields remain intact.

Termination cancels pending timers and disables the controller. Session loss invalidates authorization and can lead to the saved death fallback. Existing game respawn placement is retained: there is no new warp to the partner, navigation-safe placement, revive interaction, invulnerability window or inventory restoration. Simultaneous deaths, fall deaths, HUD restoration, network delivery and actual native respawn behavior remain unverified.

The native adaptation at RVA `0x17A16BE` changes `74 19` to a two-byte NOP while an authorized local respawn is active. The full 2,103-byte logical action function is checked across three unwind ranges, along with the native session-role getter, health-reset helper and respawn-request callback. Substate 2 uses the initial native IsHost result: the client path can wait for health/status conditions; the bypass takes the reset helper and shared transition to substate 3. This matches Dynamite's older branch behavior, inferred from dataflow rather than a retail symbol. The helper's parameters are 5.0 and a multiplier of 1.0. [Exact executable and static mapping](https://github.com/TrollTaylor/diamond-dogs-together/blob/archive/research-2026-10-23/docs/evidence/respawn-native-contract-2026-09-10.json).

In 0.10.12, the supporting role query is also detoured for the [sight and damage rules](combat-role-rules.md). Respawn accepts only that module's exact captured detour body in place of its original-byte check; all other hashes remain required. The respawn caller receives the original role result.

The controller requires successful native activation before starting its timer and rechecks before requesting respawn. Aligned two-byte exchange, instruction-cache flushing and original page-protection restoration are used. Recovery/cancellation, local host loss and mission termination request the original branch back. Failed restoration is recorded; it is not reported as successful. The executable on disk is never patched. The later transformed dispatcher consuming the request bit has not been fully decoded, and no native respawn was executed.

The original `TppMission.lua` was extracted read-only into `build/respawn-scripts-20260910/package-00.lua`: 104,102 bytes, SHA-256 `E99E6ADDD4C5135FB2D77AB58632D5E349A626EB7F10EA38301372D127F7404A`. Its exact source fingerprint gates the appended death wrapper. The TppMain controller uses the existing exact-source insertion. No complete retail script is redistributed. The native roster reader retains the [targeting contracts](https://github.com/TrollTaylor/diamond-dogs-together/blob/archive/research-2026-10-23/docs/evidence/targeting-contract-2026-09-10.json), with established client state 7 using the same mapped local/host/member accessor paths.
