## First live run: 0.10.29, PID 87784

Startup, title input, Continue and Mother Base (30050) succeeded. Native host
creation returned true, the observed session reached state 3, and host admission
set `accept=1`. Local dive input visibly animated and moved index zero's sampled
position approximately 4.78 units. A crouch-key tap did not establish a posture
change. No weapon fire, joined guest or remote actor was verified.

Return to title exposed a real ownership bug. The original mission handler
cleared the session and manager, so the later explicit-close gate refused the
already-destroyed session. The mod retained its old ownership record and refused
the destination's allocation/runtime receipts. Native gameplay rules restored,
the title menu appeared and the game quit normally. All seven save/config hashes,
the executable and the shipped Steam DLL matched the prelaunch baseline.

0.10.30 captures the session's original root and reconciles adapter ownership
after repeatedly observing empty root-session, root-manager and main-session
slots at the serialized teardown boundary. It never dereferences the old session
or invokes a lazy getter to manufacture a replacement. It also retains ownership
after a returned close request until those slots actually clear. This does not
enable reconnect or prove cleanup of every internal asynchronous resource.

## Manual guest check and worker unloading: 0.10.31/32

0.10.31 routes Diagnostic mode through the real Ctrl+F8 polling path. It returns

in Diagnostic mode. The previous client Lua fixture still expected an obsolete
automatic join receipt; its replacement passed 589 checks covering idle polling,
single attempts, mode separation, eligibility, failures and callback forwarding.
Its native receipts are simulated, not keyboard or Steam tests.

The first live attempt (0.10.31, PID 15060) exposed a different lifecycle bug
before the shortcut could be checked. ACC initialized on thread 18240 but
terminated on worker 29328. The return receipt was refused; Mother Base then
rendered with guest preparation inactive because the adapter still recorded
the ACC as running. No diagnostic input or connection was submitted. The game
returned to title and quit normally; all seven saves/config files and original
EXE/Steam DLL hashes matched the baseline.

0.10.32 records a matched termination entry/return thread independently from
the gameplay thread. An unowned scene can transfer rule cleanup to its actual
termination worker, and the next allocation transfers from that cleanup owner.
The runtime owner remains unchanged. An owned network session cannot migrate
through this path. Duplicate entries, unsolicited/foreign returns and failed
handoffs do not release the scene. Runtime input is disabled during the scope;
same-thread host admission cleanup remains available.

All 21 native suites passed on 0.10.32, including 328 simulated termination
checks using the observed thread IDs. The actual-source composer passed 20
checks and 400 concurrent selections, and its complete output parsed in Lua 5.1.
The unchanged manual guest fixture again passed 589 checks. These results do
not establish behavior of a connected guest.

## Initialization worker regression: 0.10.32/33

The 0.10.32 live Diagnostic run (PID 29368) accepted ACC termination on thread
61560, but Mother Base initialized on worker 60896 before gameplay started on
61560. The adapter refused initialization because it still required the earlier
runtime thread. Mother Base rendered normally, but guest preparation never
became active. No diagnostic shortcut or native join was attempted. The game
returned to title and quit normally; all seven save/config files and original
EXE/Steam DLL hashes matched the baseline.

0.10.33 separates matching OnInitialize entry/return receipts from
OnMissionGameStart. Only the latter establishes gameplay ownership, after both
allocation and initialization have returned. Loading-worker initialization no
longer fixes the runtime thread. The lifecycle fixture passed 91 checks; all
21 native suites passed, including initialization matching and termination
ownership cases. The actual-source composer passed 20 checks and 400 concurrent
selections, its complete output parsed in Lua 5.1, and prestart execution passed
77 checks. These fixtures simulate receipts.

The live 0.10.33 Diagnostic run (PID 20680) accepted the complete allocation,
initialization and gameplay-start sequence in Mother Base. Guest readiness was
armed and its update loop polled normally. This run used thread 88876 for all
those callbacks, so it did not reproduce the distinct initialization worker.
Automated F8 and Ctrl+F8 taps produced no recorded input, prerequisite attempt
or connection request. This does not establish that the shortcut works or that
F8 filtering works: a physical-key check is still needed to distinguish short
automation taps from a mod defect. Input observations are recorded separately.

On return to title, this same run exercised the worker cleanup fix: Mother Base
gameplay thread 88876 handed cleanup to termination worker 57152, which restored
all scoped rules and returned successfully. The next allocation on worker 33484
and initialization/gameplay on 88876 were accepted. The title menu appeared and
the game quit normally. All seven save/config files, the original executable
and shipped Steam DLL retained their baseline hashes. No physical-key result
was received before exit; shortcut behavior remains unverified.

## Final Host regression: 0.10.33, PID 52824

Mother Base host creation returned true on allocation worker 83844. Initialization
returned on 54152, and OnMissionGameStart then accepted the owned session handoff
from 83844 to 54152. Host admission was authorized and the native session reached
state 3 with `accept=1`. This run verifies an already-created host crossing
distinct loading/gameplay threads; no guest was present during the handoff.
Mother Base rendered with the local player and NPCs; a Space tap visibly produced
a dive and prone posture. No guest joined.

Return to title restored all scoped native rules without a pending retry.
Termination ran on gameplay thread 54152. The late admission-disable gate refused
its call because the host was already gone; the repeated empty-singleton reads
cleared ownership without an extra native close. The destination allocated on
83844 and initialized/started on 54152, with all boundary receipts accepted. The
title menu appeared and the game quit normally. All seven save/config files and
the original EXE/Steam DLL hashes matched the baseline. Host mode remains selected
with DLL SHA-256 `FCB0E16A5AF1EE3E1884C7EB14D2EADFD33AC83280D7C0104EA2190EA564F9B6`;
the game is closed.

This host run did not exercise termination of an owned session on a foreign
worker, explicit close with a connected guest or recovery from an asynchronous
native connection failure. The diagnostic run covered only unowned worker
cleanup. A matched initialization on a worker distinct from both allocation
and gameplay remains covered by fixtures and the earlier failure trace, not a
successful live reproduction on 0.10.33.
