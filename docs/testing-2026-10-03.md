## Blocker found: master-server login

- fuse (commit `f75b41d`, written for exe 1.0.15.3) answers the URL list with
  `GATE`/`WEB` version 17. The 1.0.15.4 client then reports *"You must update
  the game in order to use online features"* and continues offline.
- Offline, the native host session is refused: `dynamite_host=returned; result=0`.
  On September 12, while logged into Konami's server, the same call returned 1.
- The guest's connect gate reports `target_threshold=4 ready_int=3
  is_connect_ready_predicted=0`. The game's online-login state (int at
  `base+0x2BD7BB4`) has to reach 4 before a client request can start.
- Conclusion: co-op sessions need a successful master-server login. The local
  fuse first needs the URL-list version values this client build expects. Finding
  those values was paused for a user decision; see the README section "Master
  server".

## Other findings

- Character override (guest `character=quiet`): the Lua chunk ran
  (`character=apply; ... applied=quiet; type=6; bypass=1`) and the
  UpdatePartsStatus bypass installed. The readback, however, shows `vars=0; raw0=0`,
  and the guest rendered as Snake. `RegisterTemporaryPlayerType` at that point
  in `OnAllocate` does not change the free-roam Mother Base player type. This
  needs a different application point or mechanism.
- Synthetic keyboard input works once the window is focused. The new
  `tools/lab/Send-LabInput.ps1` uses an Alt tap so that Windows allows
  `SetForegroundWindow`.
- The guest instance runs at roughly 16-60 FPS while unfocused. It keeps
  running and does not pause, because both instances use true windowed mode.
