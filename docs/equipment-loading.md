# Remote equipment loading

Workspace **0.10.20** adds the missing equipment allocation used by DYNAMITE's two-player startup. It is compiled only, not installed or executed. Remote equipment and playable guest control remain unverified.

The original TppMain creates equipment ghost groups for MGO or FOB missions. Mother Base mission 30050 follows neither branch. The earlier co-op player-storage package and player-loading bypass did not add that equipment call. Pinned DYNAMITE `c90f252f8200765f66c005d6bf4357fda0c0d98e`, `moddata/standalone/TppMain.lua`, explicitly calls `TppPlayer.SetEquipMissionBlockGroupSize()` and `TppEquip.CreateEquipGhostBlockGroups({ghostCount=1})` for co-op before `StartLoadingToEquipMissionBlock`.

The adapter now inserts those calls at that same point, after vanilla equipment-group setup and before vanilla loading. It only runs in mission 30050 after this adapter's host creation or client preparation. One ghost equipment group corresponds to the immediate two-player target; this does not add four-player capacity. Original equipment loading, instance allocation and activation remain in their original order.

The source transform still requires the exact 21,634-byte TppMain SHA-256 `6542D997C3F29742FF7EA0587F7F307794586A9B7A8EE3114B58E79E7F0B6103`. It requires unique, ordered `Mission.Start()` and `TppEquip.StartLoadingToEquipMissionBlock()` anchors. The new insertion supplements the existing host-start insertion and appended lifecycle wrappers; it does not replace either original call. [Inspected source and anchor record](https://github.com/TrollTaylor/diamond-dogs-together/blob/archive/research-2026-10-23/docs/evidence/equipment-loading-source-2026-09-10.json).

`equipmentPreparationReturned` records successful return from the two setup calls, not completed asset loading. Missing APIs or a Lua error leave it false, record an error, and withhold host admission/client join. Preparation flags reset for the new co-op allocation. Calls are protected to retain ordinary mission startup and are not blindly retried after partial allocation. The game retains allocation ownership and teardown; the mod does not free equipment blocks. Failed preparation may leave a native session awaiting normal teardown.
