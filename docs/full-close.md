# Full native close wrapper adaptation

Workspace **0.10.19** implements DYNAMITE's mission-condition bypass for the existing `CloseSession` wrapper. It is compiled only, not installed or executed. A connected guest and complete asynchronous teardown remain unverified.

Pinned DYNAMITE `c90f252f8200765f66c005d6bf4357fda0c0d98e`, `hook/src/dynamitePatches.cpp`, removes a two-byte mission check so the original wrapper selects its FOB service route when the service exists. In this executable the complete wrapper spans RVA `0xA1A710..0xA1A781`. The branch at `0xA1A759` is `75 13`. The adapter atomically changes only its displacement at `0xA1A75A` from `13` to `00`: both conditional outcomes reach the same original null check. Instruction lengths and flags remain unchanged. This is equivalent to the upstream branch bypass without replacing both bytes together.

The native wrapper still obtains the current service, calls its existing slot `+0x18` if non-null, and returns directly. If the service is absent, it uses the existing session close interface. It does **not** call both routes. No concrete service method is copied, hooked or called directly by the mod. Earlier investigation identified its other interface roles through the FOB parameter-query Lua registrations, but its concrete constructor, close body and complete asynchronous lifetime remain unmapped. This change is a port of the verified caller branch and upstream lifecycle use, not a claim that those internals are now verified.

Activation occurs after the one-shot preparing-member disconnect and fresh owned-session check, immediately before Lua calls the original `CloseSession`. The wrapper and both context-accessor bodies must match complete generated contracts. The existing registry must match its constructor table; the selected context must refer to the known mission-variable storage in mission 30050. An optional service table and its close slot must resolve to the verified game image, with an executable method page. The registry/context/service pointers are reread. These structural checks do not establish a concrete service type or an atomic lifetime lease.

The first returned/failed receipt restores the byte before Lua writes result fields or formats errors. The original function handles service ownership and destruction. Byte, instruction-cache and page-protection state are tracked separately; failed restoration remains pending and is retried by native cleanup at subsequent authorized cleanup/mission boundaries. New co-op preparation is refused while native restoration remains pending. Session-close requests themselves remain one-shot and automatic reconnect stays disabled.

The branch byte is process-wide while armed. Only activation/restoration is restricted to the source-owner thread; concurrent native close callers during that interval are not excluded. A missing receipt can leave it armed until a later cleanup boundary. These timing paths, original-service behavior, protection/flush failure recovery and eventual resource release require live verification. A selected-route log means the adaptation was armed, not that the service ran or completed.
