## Developer test loop & fast test boot (mandatory for all agents)

- **Fast parallel CTest**: `tools/build.ps1` runs `ctest -j N` (default half logical processors) and uses reader registration in `%TEMP%\mgs-coop-ctest-readers` (`tools/VerifyLock.psm1`) instead of taking `%TEMP%\mgs-coop-verify.lock`, so CTests across worktrees run concurrently. Use `pwsh -File tools/build.ps1 -Fast` (`ctest -L fast`, ~6 s) during inner-loop iteration and `pwsh -File tools/build.ps1` (~90 s) for the full suite. Any new slow (>10 s, PowerShell, DX11 window, or game-folder) test must be added to `MGS_SLOW_TESTS` in `cmake/test_labels.cmake` (and `MGS_TEST_RESOURCE_LOCKS` / `tests/test_port_lock.hpp` if it shares a DX11 window, file, or fixed loopback port).
- **Fast hidden-worker boot (`docs/test-boot.md`)**: In lab hidden-worker scenarios (`tools/worker/Invoke-WorkerScenario.ps1`), prefer `boot <30010|30020|30050> [x y z yaw] [time=HH:MM] [weather=<name>]` (or `boot fast`) over manual `title` + `waitgameplay` + `wait 60000` + `worldtrigger goto=...` + `debug teleport`. `boot` sets `lab_fast_boot=1` and `lab_boot=<spec>`, skips logos/popups/title and the Mother Base arrival demo, sorties both copies together, and lands them at the target spot in ~29–32 s of game clock (~42–48 s wall time) with zero input. (`-Mode play` rehearsals keep normal `title` + `waitgameplay` because `mode=play` refuses `lab_fast_boot` / `lab_boot`.)
- **Save-seed library & low graphics**: Lab worker runs default to `-GraphicsQuality low`. Reuse named save seeds in `D:\mgs-coop-seeds` via `-SaveSeed <name>` (`-HostSaveSeed` / `-GuestSaveSeed`): `quiet-recruited` (Mother Base `30050`, Quiet unlocked), `mb-ladder` (`30050 22.61 1.80 -15.55 0`), `africa-jeep` (`30020 -656.01 1.20 877.73 62`), and `afgh-ledge` (`30010 828.18 338.20 1630.51 95`). Capture new reusable spots from closed runs with `pwsh -File tools/worker/Save-WorkerSeed.ps1 -RunId <id> -Name <seed-name>`.
- **Releasing (player package)**: `tools/package.ps1 -Friend -CheckReceipt <passing Release receipt>` writes two files into `dist/DiamondDogsTogether-<version>-<stamp>/`: the player zip `DiamondDogsTogether-<version>.zip` (no source inside) and the GPL source zip `DDT-source-<version>.zip`. Every release (tag `v<version>`) uploads **both** as assets of the same GitHub release, so the complete corresponding source is offered in the same place as the binaries (GPLv3 section 6(d)); never publish the player zip alone. The source zip's name must never start with `DiamondDogsTogether-` or `mgs-coop-friend-` (the launcher's updater takes those for the update; it also skips any asset whose name contains `source`). Record both SHA-256 lines from the package output in docs/STATUS.md.
- **Verify lock discipline**: Only hidden-worker runs, worker checks, packaging, and installs take the exclusive directory lock `%TEMP%\mgs-coop-verify.lock` (followed by `Wait-CtestReaders`). Always remove `%TEMP%\mgs-coop-verify.lock` with `Remove-Item -Recurse -Force` when finished.
